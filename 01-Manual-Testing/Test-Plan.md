# Plan de Pruebas - Aplicación Ecommerce

## 1. Introducción

El propósito de este plan de pruebas es definir la estrategia de testing para una aplicación de comercio electrónico (Ecommerce).

El objetivo es verificar que las funcionalidades principales funcionen correctamente y cumplan con los requisitos esperados.

## 2. Alcance de las pruebas

El proceso de testing abarcará las siguientes funcionalidades:

- Registro de usuarios.
- Inicio de sesión.
- Catálogo de productos.
- Carrito de compras.
- Proceso de compra (Checkout).

## 3. Objetivos de las pruebas

- Verificar que los usuarios puedan registrarse correctamente.
- Verificar que los usuarios puedan iniciar sesión utilizando credenciales válidas.
- Verificar que el sistema gestione correctamente los intentos de inicio de sesión inválidos.
- Verificar que los productos se muestren correctamente.
- Verificar que los usuarios puedan agregar y eliminar productos del carrito de compras.
- Verificar que el proceso de compra funcione correctamente.

## 4. Enfoque de las pruebas

Se realizarán pruebas manuales para validar las funcionalidades de la aplicación.

Las técnicas de testing incluirán:

- **Pruebas positivas (Positive Testing):** verificar que las funcionalidades funcionen correctamente cuando se ingresan datos válidos.
- **Pruebas negativas (Negative Testing):** verificar cómo responde el sistema ante datos incorrectos o situaciones inesperadas.
- **Pruebas funcionales (Functional Testing):** comprobar que las funcionalidades cumplan con los requisitos establecidos.
- **Pruebas exploratorias (Exploratory Testing):** explorar la aplicación para identificar posibles errores o comportamientos inesperados.

## 5. Entorno de pruebas

- **Sistema operativo:** Windows 10/11.
- **Navegador:** Google Chrome.
- **Tipo de pruebas:** Pruebas manuales.
- **Entorno:** Ambiente de pruebas (Test Environment).

## 6. Criterios de entrada

Las pruebas podrán comenzar cuando se cumplan las siguientes condiciones:

- La aplicación se encuentre disponible.
- El entorno de pruebas esté configurado.
- Los casos de prueba estén preparados.
- Los datos necesarios para realizar las pruebas estén disponibles.

## 7. Criterios de salida

Se considerará que el proceso de testing ha finalizado cuando:

- Todos los casos de prueba planificados hayan sido ejecutados.
- Los resultados de las pruebas hayan sido documentados.
- Los errores identificados hayan sido reportados.
- Los defectos críticos hayan sido revisados.

## 8. Entregables

Durante el proceso de testing se generarán los siguientes documentos:

- Plan de pruebas (Test Plan).
- Casos de prueba (Test Cases).
- Reportes de errores (Bug Reports).
- Informe de ejecución de pruebas (Test Execution Report).

## 9. Riesgos y supuestos

**Riesgos potenciales:**

- Caída o indisponibilidad de la aplicación.
- Comportamientos inesperados de la aplicación.
- Datos de prueba faltantes o incorrectos.

**Supuestos:**

- La aplicación estará accesible durante el proceso de testing.
- Los usuarios y productos de prueba estarán disponibles.
